# Phase 10 Candidate Decisions

Phase 10 is selective. Features are added only when they improve the portfolio's information value or maintenance quality without introducing disproportionate operational cost.

## Implement now

### Grounded portfolio assistant with sources
Reason: an assistant already exists. Grounding and source visibility reduce hallucination risk and make the feature materially more useful.

### Global portfolio search
Reason: the public information architecture now has Work, Insights, About, Contact, and Resume across two locales. A lightweight CMS-backed search improves navigation without a new service.

### Admin content-health checks
Reason: bilingual publishing, SEO, media alt text, evidence, and qualitative capabilities create maintainable quality requirements that are better surfaced proactively.

## Defer

### /now
Defer until there is a real cadence for maintaining time-sensitive public updates. An empty or stale /now page weakens trust.

### Recruiter mode
The current Resume route already covers the core quick-profile need. A second mode would duplicate hierarchy until evidence shows a distinct workflow is needed.

### Live project metadata
Repository activity is optional supporting context, not portfolio evidence. Additional live metadata adds external failure modes without enough visitor value.

### Private-friendly analytics
Defer until there is a concrete measurement question and a selected privacy model/provider.

### Revision history
Useful only when editing volume or collaboration makes accidental content loss a demonstrated risk.

### Scheduled publishing
Not justified for the current publishing cadence. Manual publish remains simpler and more auditable.
