# Phase 10A — Grounded Portfolio Assistant

## Goal

Make the assistant useful as a portfolio navigation aid without turning it into a generic chatbot.

## User value

Visitors can ask about experience, capabilities, and Work and receive concise answers grounded only in published portfolio content.

## Scope

- Build a structured grounding corpus from published CMS data.
- Rank the corpus against the latest user question before model generation.
- Pass only the most relevant entries to the model.
- Return source links for the entries used as grounding context.
- Render sources beneath assistant answers.
- Keep existing validation, session signing, and rate limits.
- Keep the assistant optional and deferred from first render.

## Non-goals

- No web search.
- No autonomous tools.
- No claims outside published portfolio data.
- No vector database.
- No hidden personal data or admin-only content.

## UX

- Assistant answers remain short and factual.
- Sources use canonical public routes.
- If the portfolio does not support an answer, say so directly.
- Assistant failures do not affect portfolio navigation.

## Harness

CI runs deterministic retrieval fixtures against the same production ranking module. The harness covers exact Work-title retrieval, cross-entity project-management retrieval, unrelated-query fallback, result limits, canonical source metadata, and empty-corpus behavior. It does not call the live model or consume API quota.

## Gate

- No hardcoded biography/project fallback.
- Sources are generated by server-side grounding selection, not invented by the model.
- Request validation, rate limiting, and session behavior remain intact.
- Lint, typecheck, tests, and production build pass.
